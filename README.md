# Grok Build Desktop

外部の Grok Bot から頼まれた作業を、登録した CLI エージェント（Claude Code、Codex、Grok、Antigravity、カスタム）で順に動かし、その様子と結果を見守る Windows アプリです。

現在の開発βは v0.0.6 です。Windows 用インストーラは、このリポジトリの prerelease にあります。v0.0.2 以降は、設定の「このアプリ」から更新できます。

## 起動

```powershell
npm install
npm run tauri dev
```

## 画面

左に検索、新規プロジェクトと、Grok Bot に許可したフォルダが並びます。各フォルダの下にタスクとジョブが並び、実行中・待ち・一時停止があるフォルダには印が付きます。新規プロジェクトで選んだフォルダは、Grok Bot の許可にも入ります。

タスクを選ぶと、中央にジョブのカードが並びます。カードの「ログ」で、その CLI の出力を読みやすい形か元の形で下に出せます。カードの「作業前に戻す」は、上書きするファイルと、消さずに残すあとから作られたファイルを確かめてから、そのジョブの前の内容に戻します。タスクの「タスクを終える」は確認のあとでタスクを終了にし、Grok Bot はそのタスクに続きを送れなくなります。右の列には、プロジェクトの git の状態、Grok Bot の許可と受付、開いているタスクの状態が出ます。git のリポジトリでないフォルダやコミットが無いフォルダは、右の列から空の最初のコミットを作ってジョブを受けられるようにできます。

中央の下の帯には Grok Bot の受付と実行中のエージェント、「緊急停止」が出ます。画面からジョブを頼む欄はありません。何を頼むかは Grok Bot が決めます。

設定は左下から開きます。ウィンドウの大きさは固定で、分類は表示、エージェント、連携、このアプリです。

## 連携

外部の Grok Bot が司令塔になり、このアプリに付属する `gbd.exe` を 1 回ずつ実行して作業を頼みます。アプリは頼まれたジョブを、設定の「エージェント」に登録した CLI（Claude Code、Codex、Grok、Antigravity、カスタム）で 1 つずつ順に動かし、状態、要約、変更したファイル、差分の統計、作業前の地点を短い JSON で返します。CLI の生の出力は画面に流れ、ジョブのカードの「ログ」で追えます。

Grok Bot から受け付けるのは、設定の「連携」で受付をオンにし、許可したフォルダのうち、git のリポジトリで 1 つ以上のコミットがあるものだけです。`gbd.exe` はインストール先のアプリの隣に入ります。設定の「連携」に `gbd.exe` の場所と使い方の例があり、「Grok Bot への指示をコピー」でこの PC のパスとフォルダを埋めた指示文をコピーでき、「自己診断」で Grok Bot と同じ経路を確かめられます。

```powershell
$gbd = "<gbd.exe の場所>"
& $gbd version
& $gbd submit job.json
& $gbd wait <job_id> --timeout 600
& $gbd result <job_id>
```

`job.json` は `{"project": "...", "agent": "codex", "prompt": "...", "title": "..."}` の形で、`task_id` を足すと前のジョブと同じタスクに入ります。`& $gbd help` で全部のコマンドが出ます。

成否は `status` で見ます。CLI によっては止まっても終了コードが 0 になるためです。ジョブはすべてのフォルダを通して 1 つずつ順に動きます。

次のときは止まります。

- 1 つのタスクのジョブが上限（初期値 10）に達したとき、同じ失敗が 2 回続いたとき、作業前からあったファイルが消えたときは、タスクを一時停止します。画面で再開するまで、そのタスクにジョブを足せません。
- Grok Bot からのジョブが同じプロジェクトで 30 回続くと、画面で再開するまで受け付けません。
- 1 回のジョブは、既定で 1200 秒で打ち切ります。
- 中央の下の「緊急停止」は、実行中のジョブを終了し、待ちのジョブを取り消し、Grok Bot の受付を止めます。

各 CLI の既定の引数は、確認なしの全権限を与えないものにしてあります。`--dangerously-skip-permissions` などの危険なフラグは、そのエージェントの「危険なフラグを許可」をオンにしない限り使えません。各 CLI へのログインは、それぞれの CLI で済ませておきます。
