# Grok Build Desktop

インストール済みの Grok Build と、`grok --permission-mode default agent --no-leader stdio` の ACP で会話する Windows アプリです。会話の正本は Grok のセッションに残り、このアプリはそれを写し取りません。

現在の開発βは v0.0.6 です。Windows 用インストーラは、このリポジトリの prerelease にあります。v0.0.2 以降は、設定の「このアプリ」から更新できます。

## 起動

```powershell
npm install
npm run tauri dev
```

Grok にログインしていないときは、画面の「ログイン」から `grok login` を開きます。

## 画面

左に検索、新規チャット、新規プロジェクト、登録したフォルダがあります。選んだフォルダの会話だけを罫線で出し、三角の印で畳めます。開閉には動きが付きます。設定の「開閉の動きを出す」で切れます。

セッションが開いていないときは、会話欄の中央でプロジェクトを選びます。選んでメッセージを送ると、そのフォルダの新しいセッションになります。

設定は左下から開きます。ウィンドウの大きさは固定で、分類は表示、自動承認、エージェント、連携、使用量、コマンド一覧、このアプリです。

## 連携

外部の Grok Bot が司令塔になり、このアプリに付属する `gbd.exe` を 1 回ずつ実行して作業を頼みます。アプリは頼まれたジョブを、設定の「エージェント」に登録した CLI（Claude Code、Codex、Grok、Antigravity、カスタム）で 1 つずつ順に動かし、状態、要約、変更したファイル、差分の統計、作業前の地点を短い JSON で返します。CLI の生の出力は画面に流れ、ジョブのカードの「ログ」で追えます。

Grok Bot から受け付けるのは、設定の「連携」で受付をオンにし、許可したフォルダのうち、git のリポジトリで 1 つ以上のコミットがあるものだけです。設定の「連携」に `gbd.exe` の場所と使い方の例があり、「自己診断」で Grok Bot と同じ経路を確かめられます。

```powershell
$gbd = "<gbd.exe の場所>"
& $gbd version
& $gbd submit job.json
& $gbd wait <job_id> --timeout 600
& $gbd result <job_id>
```

`job.json` は `{"project": "...", "agent": "codex", "prompt": "...", "title": "..."}` の形で、`task_id` を足すと前のジョブと同じタスクに入ります。`& $gbd help` で全部のコマンドが出ます。

画面からも、送信欄の下の「実行」を「連携」にし、エージェントを選んで依頼を送れます。画面から出したジョブは Grok Bot からは見えません。

次のときは止まります。

- 1 つのタスクのジョブが上限（初期値 10）に達したとき、同じ失敗が 2 回続いたとき、作業前からあったファイルが消えたときは、タスクを一時停止します。画面で再開するまで、そのタスクにジョブを足せません。
- Grok Bot からのジョブが同じプロジェクトで 30 回続くと、画面で再開するまで受け付けません。
- 1 回のジョブは、既定で 1200 秒で打ち切ります。
- 送信欄の「緊急停止」は、実行中のジョブを終了し、待ちのジョブを取り消し、Grok Bot の受付を止めます。

各 CLI の既定の引数は、確認なしの全権限を与えないものにしてあります。`--dangerously-skip-permissions` などの危険なフラグは、そのエージェントの「危険なフラグを許可」をオンにしない限り使えません。各 CLI へのログインは、それぞれの CLI で済ませておきます。
